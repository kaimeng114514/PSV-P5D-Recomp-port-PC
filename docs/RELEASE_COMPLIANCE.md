# RELEASE COMPLIANCE / 发布合规策略（P5D 静态重编译移植）

> 用户明确要求（2026-10-28）：**最终构建的 exe 发布版不能包含任何游戏文件；游戏文件必须由玩家从自己的游戏机/自购副本导入。**
> 参照：P5R Android 移植（Brandon04Gonzalez/p5r-android）——APK 只含引擎，游戏从玩家自备的 .nsp/.xci 读取，
> 着色器在设备上一次性本机翻译并缓存在应用目录；仓库/APK 不含任何游戏代码、资源、着色器、密钥或固件。

## 1. 硬性红线（发布包中绝对不允许出现）

| 类别 | 具体内容 | 说明 |
|---|---|---|
| 游戏可执行码 | `eboot.bin` / `p5d_true.elf` / SELF/ELF 段、任何从游戏译出的 x86-64 代码（`batch_*.cpp`、`.o`、生成器产物） | 静态重编译产物属于游戏的衍生作品，不能随包分发 |
| 游戏资源 | `data.cpk`、`vita.cpk`、`GFDPSP2.GSC`、任何 GFD/GFS/GMD/CPK 资源、影片（USM）、音频（AT9/AT3/AWB） | 全部来自玩家自己的游戏数据 |
| 游戏着色器衍生数据 | 从游戏 GXP 翻译出的 SPIR-V（当前 `C:\dev\p5d_build\spv_all` 的 4332 个 `.spv`）、着色器缓存 | 必须在玩家机器上从其自己的 `GFDPSP2.GSC` 现场生成 |
| 密钥/固件 | `prod.keys`、`title.keys`、SELF 解密 key、固件文件 | 玩家自备；程序只读取玩家提供的已解密/可读数据 |
| 存档模板等 | 任何含游戏内容的存档/表 | 只允许空目录/格式 |

## 2. 交付形态（修正后的“单一 exe”定义）

最终交付 = **引擎/运行时可执行程序（不含任何游戏数据） + 玩家自己的游戏数据**。

```
P5D_Engine.exe            ← 我们发布，只含 HLE/运行时/渲染器/（本地 AOT 与着色器翻译工具）
<玩家自备的游戏目录>        ← 玩家从自己的 PSV 游戏提取：eboot(.bin/.self/.elf) + data.cpk/vita.cpk 等
<本地缓存目录>              ← 首次运行时在玩家机器上生成：
   cache/recomp/…          ← 用玩家的 eboot 一次性静态重编译出的本机代码缓存
   cache/shaders/*.spv     ← 用玩家的 GFDPSP2.GSC 一次性翻译出的 SPIR-V
   cache/pipelines/…       ← Vulkan pipeline cache
```

**首次运行“Prepare”流程**（参照 P5R 的 “Prepare the game”）：

1. 用户选择自己的游戏文件/目录（eboot + 数据）。
2. 引擎校验数据存在性/版本，但**不复制、不上传、不打包**游戏内容。
3. **一次性静态重编译（AOT）**：把用户的 eboot ARM/Thumb 代码一次性翻译为本机 x86-64 代码缓存（本地生成，非运行时代码生成；执行路径只跑已生成的本地代码 + 解释器 fallback）。
4. **一次性着色器翻译**：解析用户数据中的 `GFDPSP2.GSC`，把其中的 GXP 程序翻译为 SPIR-V 写入本地缓存（与旧管线 `spv_all` 相同的流程，但在本机执行）。
5. 之后启动即直接使用本地缓存（可校验 eboot 哈希，若换了数据则重新生成）。

## 3. 对当前开发仓库的影响

- **仅开发用、禁止进入发布树**（需在打包脚本中显式排除/校验）：
  - `C:\dev\p5d_build\spv_all`、`spv_all_new`、`spv_2ph`、`rt_gxp`（游戏衍生）
  - `C:\dev\tmp\recomp_split\batch_*.cpp`、`batch_*.o`、`recomp_harness.exe`（含从 eboot 译出的代码）
  - `C:\dev\p5d_build\GFDPSP2.GSC`、`eboot.bin`、`p5d_true.elf`、`C:\dev\p5d_rom\**`（游戏数据）
  - `C:\dev\p5dsrc\game\**`、`private/**` 等任何游戏内容
  - 旧的 `milestone_*.png`、BMP 帧等若含游戏画面，也不能随包发布
- **发布包允许包含**：HLE/内核模拟、GXM→Vulkan 后端（我们自己写的代码）、GXP→SPIR-V 翻译器的**代码**（不是翻译结果）、AOT 重编译器（Python/工具链）的**代码**、CPK/GSC **解析器代码**。
- **发布包构建检查（必须自动化）**：新增 `tools/release_audit.py`：
  - 扫描发布目录，按扩展名/魔数（`GFS0`、`GSC0`、`GXP\0`、`CPK `、`USM`、`P5D` 标识、eboot 段特征）拒绝；
  - 可选：对玩家可见的说明文档声明“不包含游戏文件、需要自己的合法副本”。

## 4. 关键技术决策（待实施）

1. **AOT 编译器随包方式**：发布 exe 内置“本地一次性重编译”能力。可选：
   - (a) 移植成熟编译器（LLVM/clang）随包 → 体积大；
   - (b) 把我方 ARM/Thumb→x86-64 生成器改为**直接输出机器码**（不经 C++ 编译器）→ 工程量中等，体积小；
   - (c) 先发布“开发者版”：玩家需自行安装编译工具链运行重编译器（不合“开箱即用”，但合规）。
   建议中期目标 (b)：静态一次性编译、结果缓存，执行路径无 codegen。
2. **着色器翻译器随包**：把现有 GXP→SPIR-V 管线（`spv_all` 的生成器）打包进 exe/工具，首次运行时从玩家的 GSC 生成本地缓存。
3. **旧 GXM→Vulkan 后端接入**（M661 计划）不变；只是发布树中不带任何游戏数据。
4. **回归检查**：`run_all_regressions` 增加“发布树合规扫描”阶段（无游戏魔数/无大文件白名单外文件）。

## 5. 与目标的对应关系

- 目标“产出单一 PC 可执行程序 + 原版游戏数据”：解释为 **引擎程序（我们发布） + 玩家自备的原版游戏数据（不随包）**；
- 目标“原版 eboot/SELF 原样加载执行”：玩家导入的原始 eboot 原样读取（不修改内容）；CPU 采用“**本机一次性静态重编译**”后执行；
- 目标“所有游戏着色器 AOT 预编译为 SPIR-V”：在玩家机器“Prepare”阶段完成，缓存本地，不进发布包。
